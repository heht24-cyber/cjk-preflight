## 二、竞品动态（overfull）

最近提交（11-18）：Reference sources 打磨、CI 修复、venue 规则更新、release 工程。
唯一开放 issue #114 是引文源维护。
**判断**：作者单人高强度维护，注意力全在英文引用生态（CrossRef/OpenAlex/ACL）。中文支持不在其路线图上。窗口期保守估计还有 3-6 个月（开源项目单人文档型工具转向成本高）。

## 三、需求信号

1. **字体嵌入惨案是普世问题**：英文世界 5,022 条相关 issue，中文 276 条，合计「期刊要求字体嵌入」语境 10,749 条——这是投稿/学位论文的**硬性拒稿理由**
2. **中文 PDF 工具流量已被验证**：PDFMathTranslate（2024-09 创建，EMNLP 2025 Demo）38,583★——中文研究者对"处理 PDF 的工具"有巨大且被验证的需求
3. **CTeX-kit 官方 issue 区**（1060★，中文 LaTeX 基础设施）的开放 issue 全是源码层排版问题（#1118 直引号间距、#1124 多行公式间距、#992 命令边界间距）——**没有一条是"检查成品"**，说明成品检查连需求都还没被开源社区意识到（蓝海确认）

## 四、相邻市场（顺手可扩）

- **日语市场同样空白**：禁則処理（kinsoku）是日本排版核心概念，但 GitHub 无独立检查工具。本工具的检查项天然 CJK 通用，改名 `cjk-` 而非 `chinese-` 是正确决策
- **Word/WPS 用户 > LaTeX 用户**：本机实测 3/3 Word 转 PDF 字体未嵌入。中国大陆高校毕业论文提交前检查是天然场景（学校格式审查是刚需痛点）

## 六、发布策略建议（优先级排序）

1. **先 GitHub 后 PyPI**：GitHub 零门槛零审核，PyPI 新账号有等待期；先攒星再发包
2. **首屏动图 + 一句话**："在你把 PDF 交出去之前，查出中文排版里最伤的那些问题"
3. **发布渠道顺序**：GitHub → V2EX / 知乎 LaTeX 话题 / CTeX 论坛（中文 LaTeX 用户聚集地）→ r/LaTeX（英文位，强调 CJK 通用）
4. **钓句子**（从本调研提炼）：中国高校毕业论文格式审查、期刊投稿字体嵌入硬性要求、"Word 转 PDF 100% 字体未嵌入"（本机实测数据）
5. **命名防御**：仓库建立后尽快在 README 挂 PyPI 徽章占位

## 七、风险与不足

- GitHub 检索受 API 限流影响，样本可能有遗漏（缓解：多关键词交叉）
- 星数≠需求：PDFMathTranslate 的星来自翻译需求，不完全等于检查需求
- overfull 作者若看到中文需求可能快速跟进（缓解：先发 + CJK 深度做透——禁则表、GB/T 15834 规范引用这些他短期做不了）
